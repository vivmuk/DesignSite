Description

Datadog-school operations room: a navy-dark canvas packed with sparklines, latency histograms, status dots and severity badges, where every pixel reports something. Screens feel monitored, not decorated. For devops platforms, monitoring products and enterprise consoles.

Agent build prompt — copy this into any AI agent

ROLE: You are a senior front-end engineer building a monitoring platform's marketing page in the Observability Ops Console style — dense, live and relentlessly informative. LOOK: navy #0B1220 background, panels on #111B2E with #1E2C4A borders; text #DCE6F5, muted #64789C, primary blue #3B82F6, warn amber #F59E0B, error red #EF4444, ok green #22C55E. Import: https://fonts.googleapis.com/css2?family=Inter+Tight:wght@600;700&family=Inter:wght@400;500&family=JetBrains+Mono:wght@400;600&display=swap. Every numeric value renders in JetBrains Mono, tabular-nums. Panels are compact: 12px padding, 1px borders, small-caps titles. LAYOUT: top nav with a live incident counter badge; hero split as an actual dashboard — headline left, a 2×3 wall of live panels right (sparklines, status grid, p99 histogram); stats band of five KPI tiles counting up; a data-table section listing recent incidents with severity badges; notification-center style alert rail; CTA framed as 'start monitoring in 90 seconds'. MOTION: sparklines append a point every 2s and shift with a 300ms linear transition (canvas or uPlot); status dots pulse an expanding ring scale 1→2 fading over 2.4s; KPIs count up 1s ease-out when visible; panels lift 2px with accent border on hover in 180ms. SIGNATURE: (1) pulsing status dot grid; (2) sparkline-prefixed panel titles; (3) severity badge taxonomy used consistently. CONSTRAINTS: semantic HTML, at least 4.5:1 contrast, responsive — the panel wall stacks under 900px, prefers-reduced-motion freezes sparkline appends, keep JS under 15KB, throttle rAF.
