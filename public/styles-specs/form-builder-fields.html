Description

An exhaustive form-system kit: every input variant and state — default, focus, filled, error, disabled, loading — plus inline validation, repeatable array fields with reorder handles, and a submission summary. For SaaS, admin tools, and fintech that need forms to feel engineered. The signature is state completeness — nothing is left undefined.

ROLE: Build a single-page form-system showcase in the Form Builder Fields style. LOOK: background #F8F9FB with a soft gradient, white cards, text #1C2130, muted #6E7688, accents #6C5CE7 (violet) and #00B8A9 (teal success), border #E4E7EE, error #D64545. Load https://fonts.googleapis.com/css2?family=DM+Sans:wght@400;500;700&family=JetBrains+Mono:wght@500&display=swap — DM Sans for UI, mono for field tokens like FN-014. LAYOUT in order: (1) header with kit name and version badge; (2) state gallery: one text input rendered in five states — default, focus, filled, error, disabled — each labeled; (3) input variant grid: text, select, textarea, checkbox group, radio cards, file dropzone; (4) repeatable array field with three rows, drag handles, add/remove; (5) inline validation demo with helper and error copy; (6) submission summary receipt; (7) footer. MOTION: focus rings draw via stroke-dashoffset over 200ms; error messages slide down 6px with fade over 180ms as borders transition red in 150ms; dragged array rows lift with shadow while siblings part with 260ms spring cubic-bezier(0.34,1.56,0.64,1); submit morphs the button to a check over 400ms and raises a toast 8px in 250ms. SIGNATURE: (a) the five-state gallery, (b) array rows with drag reorder, (c) labeled field tokens. CONSTRAINTS: semantic HTML with label-for everywhere, aria-invalid and aria-describedby on errors, 4.5:1 contrast, single column below 700px, no frameworks.
